# Issue thread snapshot

Issue: #1606 Restore timing metadata for moderation responses
Opened by: @DanielButler1

## Original issue body

## Problem

Moderation responses do not appear to include the expected timing metadata, making latency and request-stage analysis incomplete.

## Investigation scope

- Define the timing fields expected for moderation requests.
- Trace request, upstream, processing, and response timing collection through the moderation executor and response mapper.
- Compare streaming/non-streaming or provider-specific paths where applicable.
- Verify behavior across multiple moderation models/providers.

## Acceptance criteria

- Successful moderation responses include the documented timing metadata.
- Timing values use the correct units and remain internally consistent.
- Failed and short-circuited requests expose intentional timing behavior.
- Multiple representative moderation routes are tested.
- Regression coverage verifies timing collection and serialization.
- Public types/docs are updated if the intended response contract was previously unclear.
