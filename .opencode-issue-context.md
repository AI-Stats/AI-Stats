# Issue thread snapshot

Issue: #1605 Fix provider detection for text-to-speech models
Opened by: @DanielButler1

## Original issue body

## Problem

The text-to-speech API does not reliably detect that supported models have providers. Valid TTS models can therefore appear unavailable or fail before routing.

## Investigation scope

- Trace TTS model identity from catalog metadata through API-model mappings and provider eligibility.
- Review capability/modality matching, operation IDs, aliases, and provider availability filters.
- Compare exact-route and automatic-route behavior.
- Test multiple TTS models and providers to avoid a provider-specific workaround.

## Acceptance criteria

- Supported TTS models resolve at least one eligible provider when provider coverage exists.
- Providerless, disabled, or unsupported models return an accurate and actionable response.
- Exact and automatic routing use consistent model/provider identity.
- Representative requests succeed across more than one model/provider where coverage permits.
- Regression tests cover the provider-detection root cause.
- No unrelated text or audio operation is regressed.
