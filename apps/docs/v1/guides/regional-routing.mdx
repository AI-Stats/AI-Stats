Phaseo separates regional controls into two levels so the guarantee matches the
part of the request path you need to constrain.

## Level 1: regional upstream routing

Use `provider.region` on the normal API hostname when the upstream model provider
must execute and handle request data in a particular region.

```json
{
  "model": "google/gemini-3.1-flash-lite",
  "input": "Summarize this ticket.",
  "provider": {
    "region": "eu"
  }
}
```

`region: "eu"` is shorthand for requiring both `required_execution_region: "eu"`
and `required_data_region: "eu"`. Explicit fields remain available when the two
requirements differ.

This policy filters eligible upstream offers before ranking and fails closed when
none satisfy it. It does **not** constrain where the Phaseo gateway itself runs.

## Level 2: EU content path

Use `https://eu.api.phaseo.app` when both of these must be enforced:

- TLS termination and gateway request processing occur within the EU.
- Upstream routing cannot leave the EU execution and data-handling policy.

The hostname applies an immutable EU policy floor. A request cannot weaken it by
setting another region. Phaseo returns these confirmation headers:

```text
x-phaseo-residency-level: content-path
x-phaseo-processing-region: eu
```

The regional hostname fails closed with `503 regional_content_path_unavailable`
until its infrastructure has been provisioned and verified. Requests also fail
closed when no eligible EU upstream offer exists.

## What Level 2 does not claim

Level 2 is a content-path guarantee, not full account-data residency. Compact
operational, usage, cost, billing, authentication, and request metadata may still
be stored outside the EU. Detailed prompt and response telemetry, gateway replay,
and optional I/O payload logging are disabled for the regional content path.

If a contract requires all database records, logs, backups, analytics, support
systems, and account data to remain in the EU, that is a separate full-residency
deployment requirement.

## Combine regional routing with ZDR

Add `require_zero_data_retention: true` when the upstream must also support a
zero-data-retention policy:

```json
{
  "provider": {
    "region": "eu",
    "require_zero_data_retention": true
  }
}
```

See [Route only to EU or ZDR-capable providers](../cookbook/route-only-to-eu-or-zdr-providers.mdx)
for complete request examples.
