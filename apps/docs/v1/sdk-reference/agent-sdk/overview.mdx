Use a Phaseo Agent SDK when your application needs to call tools, run more than one model step, or pause and resume work safely.

The SDK runs inside your application. You choose where it is deployed and where returned run state is stored, while model requests continue to use Phaseo for routing, policy, and usage tracking.

TypeScript defines the reference contract. Python, Go, C#, Java, PHP, and Ruby implement the same core runtime behavior through language-native callbacks, streams, concurrency, and state interfaces.

## Agent SDK or Client SDK?

| Choose | When you need |
| --- | --- |
| **Client SDK** | A direct model request, streaming response, embedding, image, audio, or another API operation that your application controls itself. |
| **Agent SDK** | A bounded loop in which a model can call local tools, inspect the results, and continue until the task is complete or needs approval. |

<Tip>
  Start with a [Client SDK](../typescript/overview) for a single request. Move to an Agent SDK when your application needs tool execution or multi-step control.
</Tip>

## Start with TypeScript

Install the client and Agent SDK packages:

<CodeGroup>
```bash npm
npm install @phaseo/sdk @phaseo/agent-sdk
```

```bash pnpm
pnpm add @phaseo/sdk @phaseo/agent-sdk
```

```bash yarn
yarn add @phaseo/sdk @phaseo/agent-sdk
```

```bash bun
bun add @phaseo/sdk @phaseo/agent-sdk
```
</CodeGroup>

Define one local tool and run an agent:

```typescript
import {
  createAgent,
  createGatewayAgentClient,
  defineTool,
} from "@phaseo/agent-sdk";

const lookupOrder = defineTool({
  id: "lookup-order",
  description: "Look up an order by ID.",
  async execute(input: { orderId: string }) {
    return { orderId: input.orderId, status: "shipped" };
  },
});

const supportAgent = createAgent({
  id: "support-agent",
  model: "phaseo/free",
  instructions: "Use the order tool when needed, then answer concisely.",
  tools: [lookupOrder],
});

const result = await supportAgent.run({
  input: "Has order 123 shipped?",
  client: createGatewayAgentClient({
    clientOptions: { apiKey: process.env.PHASEO_API_KEY! },
  }),
});

console.log(result.output);
```

The agent can request `lookup-order`, receive the local result, and use it in the final answer. Add persistence or approval rules only when the workflow needs them.

## How a run works

1. Your application sends the current input and run state to the agent.
2. The agent requests a model response through Phaseo.
3. If the model calls a tool, the tool runs inside your application.
4. The result is added to the next model step.
5. The run finishes, pauses for approval, or returns state that your application can save and resume.

Use explicit limits for steps, retries, tool execution, and cost wherever the selected SDK supports them.

## Cross-language capability contract

Every supported Agent SDK includes:

- validated executable tools, bounded concurrency, timeouts, and selectable tool-error handling
- per-tool and conditional approvals, human review, manual tools, and exact tool-call decisions on resume
- progress-producing tools with preliminary-result events
- model streaming with replayable text and full-event consumers, plus language-native event projections
- composable step, duration, token, cost, tool-call, finish-reason, and custom stop conditions
- dynamic model settings, instructions, sampling parameters, tool sets, and mutable application context
- serializable run state with an optional application-owned load/save interface
- normalized token and cost summaries, finish reasons, warnings, lifecycle events, cancellation, retries, and Devtools capture

The language pages show the native API for each runtime. Rust and C++ Agent SDKs are intentionally deferred while their Client SDK packaging and release paths mature.
